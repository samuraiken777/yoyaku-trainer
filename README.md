# 要約トレーニング

**公開URL: https://samuraiken777.github.io/yoyaku-trainer/**

高校生（高3・共通テスト／私大レベル）が日本語の**要約問題**を自習するためのウェブアプリ。
文章を登録すると採点基準が自動で作られ、キーボード入力または**手書き解答の写真**を出すと、観点別に添削が返る。

- 静的ファイルのみ。ビルド不要、サーバー不要。
- 問題・解答・採点結果は**その端末のブラウザ内（IndexedDB）にだけ**保存される。
- 採点は Claude API を直接ブラウザから呼ぶ（BYOK方式）。

---

## 仕組み

採点が毎回ぶれないように、**採点基準を先に固定する**2段構えになっている。

1. **問題分析（問題1つにつき1回だけ）** — 本文を読ませて、模範解答・採点項目（4〜8個、各項目に本文中の根拠つき）・保持すべき論理関係・つまずきやすい点を作る。これを問題と一緒に保存する。
2. **採点** — 保存済みの採点基準に沿って添削する。**字数と本文からの引用はJavaScript側で数えて**モデルに渡す（数え間違いを構造的に防ぐため）。

手書き写真は必ず「読み取り → 本人が確認・修正 → 採点」の順に進む。OCRの誤読がそのまま減点になるのを防ぐため。

### 字数の扱い

モデルに「◯字以内で」と指示しても日本語の字数は正確に数えられないので、**返ってきた文章をJS側で実測し、超過していたら圧縮し直させる**（[`js/fit.js`](js/fit.js)）。対象は模範解答と「解答を直した例」の2つ。最大2回まで詰め直し、それでも収まらなければ実測値をそのまま表示する（直らなかったことは隠さない）。

数えるのは常にこちら、直すのはモデル、という役割分担にしている。

### 「解答を直した例」の差分表示

生徒の解答と直した例の差分を1文字単位（最長共通部分列）で取り、**取り消し線＝削ったところ／下線＝足したところ**で色分けする。何をどう直されたのかが一目でわかることを狙っている。差分の下に、直したあとの文章もそのまま出す。

### 続けるための仕掛け

毎日1問を続けるための要素を入れてある（[`js/daily.js`](js/daily.js)）。

- **今日の一言** — 日本語と英語を1つずつ、トップページに表示。日付から決まるので、同じ日に何度開いても同じ／日が変わると次の一言になる。全15組なので2週間以上は重複しない。分析・採点の待ち時間中にも同じ一言が出る（待ち時間が無駄にならないように）
- **連続日数** — 「🔥 3日連続」「✓ 今日はもう解いた」「今日の1問がまだ」を表示。今日まだ解いていなくても、昨日まで続いていれば記録は生きている扱いにする（朝の時点で0にしない）

### 観点の5分類

`要点網羅` / `不要要素の混入` / `論理関係の保持` / `字数遵守` / `日本語表現`

採点項目ごとにこのタグが付き、履歴画面で「いま何が弱いか」が推移で見える。

## セットアップ

### 1. APIキーを用意する

[Anthropic Console](https://console.anthropic.com/) で APIキーを発行する。

> **必ず、このアプリ専用の Workspace を作り、月額の支出上限を設定してから、その Workspace のキーを発行すること。**
> キーはブラウザの localStorage に平文で保存され、開発者ツールから読める。これは BYOK 方式である以上避けられない。
> 守りは「見えなくする」ことではなく「**上限をかける**」こと。漏れても被害が上限で止まる状態にしておく。

### 2. ローカルで動かす

ES モジュールを使っているので `file://` で直接開くと動かない。HTTPサーバー経由で開くこと。

```bash
npx serve .
```

Python でも可（この環境で動作確認済み）:

```bash
"C:\Users\samur\AppData\Local\Programs\Python\Python312\python.exe" -m http.server 3210
```

表示された `http://localhost:3210` などをブラウザで開く。

### 3. アプリにキーを登録

右上の ⚙ → APIキーを貼り付け → **「接続テスト」**で ✓ が出ることを確認 → 保存。

## 使い方

1. **問題をつくる** — 2通りある。
   - **貼り付け**: 問題集やプリントの本文を貼り、指定字数を選んで「分析」
   - **AI生成**: テーマ・難易度・分量を指定してオリジナルの評論文を書かせる → 内容を確認して「分析」
2. **解く** — 本文を読んで要約を書く。字数カウンタが目標±10%に入ると緑になる。
   - **本文をなぞるとマーカーが引ける**（マーカーを押すと消える。問題ごとに保存される）
   - 手書きの場合は「手書きを撮影」→ 写真を選ぶ → 「読み取る」→ **文字起こしを確認・修正** → 採点
3. **添削を読む** — 点数、観点別スコア、採点項目の○△×、表現の指摘（解答にハイライト）、総評、**自分の解答を直した例**、模範解答。書き直し例と模範解答には字数が出る。
4. **レポートにする** — PDFで保存・印刷、またはHTMLファイルで保存して人に送る（下記）。
5. **記録を見る** — 総合点の推移と、観点別の平均（直近5回）。一番弱い観点が名指しで出る。

## 品質と速さの切り替え

⚙の設定画面で4段階から選ぶ。演習画面の「採点する」の下に現在のモードが出る。

| モード | モデル / effort | 目安 |
|---|---|---|
| 速さ優先 | Sonnet 5 / low | 10〜15秒・1問約7円 |
| **標準（既定）** | Sonnet 5 / medium | 15〜30秒・1問約10円 |
| 質を優先 | Sonnet 5 / high | 25〜45秒・1問約13円 |
| 最高品質 | Opus 5 / high | 40〜90秒・1問約25円 |

- 数をこなす日は「速さ優先」、じっくり1問やる日は「質を優先」
- 採点が浅い・見落としが多いと感じたら1段上げる
- 手書きの文字起こしだけは、どのモードでも effort は low 固定（考える作業ではないため）。ただしモデルは追従するので、「最高品質」にすると読みにくい字にも強くなる

設定は端末に保存され、次回以降も引き継がれる。中身は [`js/config.js`](js/config.js) の `PRESETS` にまとまっている。

> Sonnet 5 は 2026-08-31 まで導入価格（$2/$10 per MTok）。以降は $3/$15 になるので、上の金額は1.5倍程度になる。
> 右上のバッジにこの端末での累計利用額（概算・1USD=150円換算）が出る。正確な請求額は Console で確認すること。

## レポート出力

添削結果の画面から、問題文・解答・添削をまとめた1枚のレポートを出せる。

- **📄 PDFで保存・印刷** — ブラウザの印刷ダイアログが開く。送信先で「PDFとして保存」を選べばPDFになる（iPhoneは共有ボタン →「プリント」→ プレビューをピンチアウト → 共有）。ファイル名は `要約添削_タイトル_日付` が既定で入る。
- **💾 HTMLで保存** — 単体で開ける .html ファイルを保存する。メールやLINEに添付して送れる。

レポートには、点数・観点別スコア・採点項目の○△×・指摘のハイライト付き解答・総評・書き直し例・模範解答・本文（採点根拠と本人のマーカー付き）が入る。A4縦で組んである。

> **PDF生成ライブラリを使っていない理由**：jsPDF 等でPDFを直接作るには日本語フォントを数MB同梱する必要があり、スマホでの読み込みが重くなるうえ文字化けのリスクもある。ブラウザの印刷機能を経由すれば、日本語が確実にきれいに出て、文字も選択・検索できるPDFになる。

## iPad / iPhone での設定

公開URLができたら、実際に使う端末で次をやる。

1. **Safari で公開URLを開く**（Chrome等でも動くが、Safariが一番素直）
2. **ホーム画面に追加** — 共有ボタン → 「ホーム画面に追加」。アドレスバーのない全画面で開くようになる
   - 以後は**必ずこのアイコンから開く**。Safariのタブとホーム画面アイコンでデータが別扱いになることがあるため、入口を1つに固定しておくと混乱しない
3. **⚙ からAPIキーを登録 → 接続テスト** で ✓ を確認
   - キーの持ち込みは、iCloudメモに貼っておく／パスワードマネージャに入れておく／AirDropで送る のいずれかが楽
4. **問題を1つ作る** — 貼り付けでもAI生成でもよい
5. **手書きを試す** — 紙に要約を書いて「手書きを撮影」→ 撮る → 「読み取る」→ 文字起こしを確認 → 採点

### 注意点

- **データは端末ごとに独立している。** PCで作った問題はiPadには出てこない。息子さんが使う端末で問題を作るのが基本運用。
- **プライベートブラウズでは保存されない。** 通常のタブ（またはホーム画面アイコン）から使うこと。
- **Safariの履歴を消すと問題も消える。**「履歴とWebサイトデータを消去」はIndexedDBも消す。大事な採点はレポートをPDFかHTMLで保存しておく。
- **APIキーは息子さんの端末に平文で残る。** 開発者ツールから読める。防御はConsole側の**支出上限**だけなので、必ず設定しておく。
- 写真がHEICでも動く（Safariが読める）。もし読めない写真があれば「設定 → カメラ → フォーマット → 互換性優先」でJPEGにできる。

### Dropbox に置いても動かない

ESモジュールを使っているため、ファイルを直接開く（`file://`）方式では動かない。必ずHTTPサーバー経由（GitHub Pages かローカルサーバー）で開くこと。

## ファイル構成

```
index.html      画面（5ビューをタブ切替）
style.css       ライト／ダーク両対応
js/
  daily.js      今日の一言（全15組）と連続日数の計算
  config.js     品質と速さのプリセット（モデルとeffortの対応表）
  main.js       画面遷移・イベント配線・本文マーカー
  report.js     レポートの組み立て・印刷・HTML書き出し
  api.js        Claude API ラッパ（キー管理・CORSヘッダ・リトライ・費用積算）
  prompts.js    分析／採点／生成／OCR／字数調整 のプロンプトとJSONスキーマ
  fit.js        字数超過の検出と詰め直し
  grading.js    字数カウント・本文引用の検出・差分（JS側で決定的に計算）
  storage.js    IndexedDB
  ocr.js        画像の縮小とJPEG化（長辺2576px上限）
  render.js     添削結果のハイライト描画・履歴グラフ
```

## 技術メモ

- ブラウザから `api.anthropic.com` を直接叩けるのは、リクエストに
  `anthropic-dangerous-direct-browser-access: true` ヘッダを付けているため（Anthropic が公式にサポートしているBYOK向けの機能）。
- 出力は structured outputs（`output_config.format`）でJSONスキーマを強制しているので、UI側のパースは安定している。
- 画像は長辺2576pxまで（Opus 5 / Sonnet 5 の高解像度対応の上限）。手書きは解像度が効くので落としすぎない。
- 撮影した写真は保存していない（読み取り後に破棄）。IndexedDBに残るのは文字起こし結果だけ。

## 問題文の入手先

「貼り付け」と「AI生成」の2通り。白書・青空文庫からの自動取得は使わない方針にした（貼り付けとAI生成で足りるため）。

## 注意

- 貼り付けた本文は採点のため Anthropic の API に送信される（30日保持）。手持ちの問題集を家庭学習に使う範囲を想定している。
- **問題文をこのリポジトリにコミットしないこと。** 本文はIndexedDBの中にだけ置く。
- 入試過去問の自動収集はしていない（現行の評論文は著作権保護下にあるため）。
